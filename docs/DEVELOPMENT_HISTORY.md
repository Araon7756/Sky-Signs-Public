## 为什么这样实现

### 先完善原版天气，再扩种类

维护者明确选择先稳定晴／雨／雷暴及切换体验。复用原版雨雪、遮挡、群系降水和闪电，减少直接替换渲染与玩法的风险。当前预报是已保存的下一阶段，自动切换直接采用它，避免仪表预报与实际转换各自随机。

### 服务端权威，客户端只呈现

天气、风况、气候读数和命令在服务端计算；图形类在独立 client 源集。单机仍有集成服务器，不能据此假设专用服务器已通过。四种仪器通过共享状态观测同一套天气，不各自维护独立天气循环。

### 方块实体只用于需要动态读数的对象

气象站右键按需报告，没有独立方块实体；风向标方块实体提供转子渲染上下文，不另存一套天气。两个表盘共享读数方块实体。转子与指针动态、外壳静态，避免整台仪器每帧动态重绘。修改旋转轴或模型高度时必须同步检查碰撞和库存预览。

### 性能先分离成本，不假设已经缓存

气压计不需要附近水体，故不调用完整湿度测量；仪表采样错峰避免同 tick 峰值，读数不变不发送方块实体更新。湿度最坏仍有 245 次查询，气象站／forecast 也会触发湿度计算。水体缓存与变化阈值网络同步仍是计划。

### 群系字段优于群系 ID 白名单

使用 `hasPrecipitation`、`downfall`、温度与位置，适应遵循原版字段的地形数据包；限制异常范围，避免干旱群系因全局雨而等同雨林。高海拔样本的实际雨／雪遵循原版，不因群系名称带 snow/ice 就强制下雪。没有修改世界生成。

### 光影兼容采用保守退让

开发历史中出现 Photon v1.3b 闪电时大面积黑屏。当前避免在 Iris 光影路径施加本模组的降水顶点偏移，而非修改用户光影 ZIP 或隐藏闪电。用户反馈与局部测试支持这个策略，但新 Iris、Sodium、光影或其他天气模组仍需回归。

### 版本化文本与存档有不同职责

报告从预渲染字符串变成 `Text`，所以改用 `station_report_v2`，避免对旧解码器发送新格式。存档结构版本则独立于发布版本和 Minecraft DataVersion；新增 UI 不应递增结构版本。

迁移保留有效目标、预报、时间戳和未知字段；未来版本保存原载荷并拒绝对应写操作。缺迁移步骤不抛解码异常，以免原版 PersistentStateManager 回退默认值。该保护不是全世界降级保证，不替代用户备份。

### 测试记录有边界

历史玩家手测、生成旧字段 fixture 的自动测试、真正历史世界升级，是三种不同证据。性能探针记录短时间主世界 tick 与帧间隔，不能代表长期服务器容量。多人测试曾因第二客户端原生崩溃未完成，维护者随后决定暂缓专用服务器排查。

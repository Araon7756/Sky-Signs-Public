# Sky Signs 存档格式与迁移

从 0.6.0-beta.6 开始，Sky Signs 为自身的数据结构记录正式版本号。它与模组发布版本、Minecraft 的外层 `DataVersion` 都是不同概念；仅修改界面、翻译或算法，不应因此增加存档结构版本。

## 当前结构

| 数据 | 位置 | 当前结构版本 |
| --- | --- | --- |
| 天气与预报 | 各维度持久化管理器的 `skysigns_weather.dat`，位于外层 `data` 中 | 2（P1 候选） |
| 风向、强度及目标 | 各维度持久化管理器的 `skysigns_wind.dat`，位于外层 `data` 中 | 1 |
| 气压计／湿度计 | 方块实体 NBT 的 `skysigns_data` 区域 | 1 |

版本字段为 `skysigns_data_version`，必须是 NBT Int。风向标本身没有额外观测值存档，气象站也没有独立方块实体数据；不要给无数据的对象增加无意义的结构版本。

仪表仍写出原有根级 `reading_percent`，以保留旧读数字段；新代码以 `skysigns_data` 中的读数为准。这不代表允许任意降级，尤其不能依赖不具备版本保护的旧模组安全读取未来存档。

## 版本 0 → 1

没有版本字段的 Alpha/Beta 数据视为结构版本 0。迁移入口为 `SaveDataMigrations.upgrade`，按数据类型逐级升级，不直接跳过中间版本。

- 不改变已有的有效天气、预报、阶段起点、变化截止 tick 或自动／手动模式。
- 不重抽风的目标方向和目标强度；缺少目标字段时沿用旧读取逻辑，以当前方向／强度为默认值。
- 缺少模式时默认自动；旧天气和风况的 `initialized` 默认 true，与历史加载行为一致。
- 仪表已有读数移入独立区域，默认读数仍为 50，范围仍限制为 0～100。
- 新增结构版本与明确的初始化字段。天气／风况迁移后标记为需要保存；仪表迁移后在第一次服务端采样时标记保存，即使采样值没有变化。
- 旧仪表缺少方块实体时，沿用区块加载补建逻辑并标记持久化，不修改方块位置、类型或朝向。
- 天气／风况原始载荷以及仪表独立区域内的未知字段保留，不仅重建已知字段。
- 非有限风值（NaN、Infinity）使用安全有限值，避免污染插值；这类损坏值不属于“有效值原样保留”的承诺。

迁移基于输入副本进行。完整 WIND/METER 1 或 WEATHER 2 再次加载不重复迁移，不重新安排预报或倒计时。保存使用 Minecraft 原有的存档流程；本版没有自动创建备份，安装前需要自行备份世界。

## WEATHER 1 → 2（P1 候选）

仅 WEATHER 递增；WIND/METER 保持 1。新增 `from_type`、`precursor_at`、`transition_end`、`curve_mode`、`anchor_at/anchor_end`、五个 Float 基值锚点及 `paused/pause_at`。类型与时间语义见 [P0 字段表](V0_7_DESIGN.md#61-字段表与不变量)；候选实现与验收见 P1 交付（原始证据保留于 Private 档案）。本候选不是发布记录。

1→2 不使用 RNG 或世界当前时间。保留有效 type/forecast/S/T/automatic/initialized，from_type=旧 type，P=T−min(1200,(T−S)/2)，E=T，曲线为 LEGACY。锚点为旧 type 基值，接入区间 S/S，paused=false、pause_at=0。v0 先经过现有 0→1 步骤，再独立 1→2；未知键保持。旧同天气预报和过期 T 都保留。

LEGACY 气压维持旧整阶段 smoothstep 与相同微扰；湿度和风区间在剩余旧计划使用旧 type。首次运行到 T 后只完成一次，采用已保存目标，再以 400 tick REBASE 从未扰动基值接入下一计划。手动 LEGACY 不自动推进；initialized=false 在写入入口初始化。

v2 时间字段必须为 Long，锚点必须为有限 Float，天气／曲线必须是已知 String 枚举，模式字段为 0/1 Byte。关键字段缺失、时间反序／差值溢出、风区间反序或非法暂停进入原载荷只读保护，不抛出解码错误让框架新建默认状态。手动 REBASE 的 S=P=T=E 且 anchor_end=S+400 是合法例外。自动暂停用 pause_at 冻结有效 tick；恢复整体平移计划与锚点，暂停中命令使用冻结时刻建立替代计划。

## 未来／无效版本保护

大于当前支持版本、负数、非 Int 的显式版本号不会当成旧格式重置。

- 天气／风况进入只读保护，停止对应的自动状态更新。
- 修改对应状态的 Sky Signs 命令返回失败，并显示中英文错误消息。
- 只读仪表停止采样，右键显示保护提示。
- 天气／风况再次序列化时返回原始载荷副本；仪表写回原始 `skysigns_data` 区域，不把未来版本降成当前支持版本。
- 日志提示版本不支持，并建议换用兼容版本或恢复备份。

如果以后增加版本号却遗漏中间迁移步骤，也返回只读的原始数据，而不抛出解码异常触发原版管理器的默认值回退。

只读时，已知字段可用于尽力显示，不能视为对未来结构含义的完整解释。该机制保护的是上述模组自有数据载荷，不是整个世界的降级兼容保证；原版 `/weather` 和其他模组也不受 Sky Signs 命令保护约束。方块破坏／世界编辑仍会正常删除对应数据。

## 后续如何扩展

1. 只有结构或字段含义发生不兼容变化时，增加对应 `Kind` 的版本号。
2. 在逐级迁移入口增加 `n → n+1`，保留旧迁移步骤。
3. 定义新增字段默认值、单位及缺失字段处理；不要在迁移中使用随机预报或依赖当前世界时间重抽已有值。
4. 保留未知字段，避免过早丢弃扩展信息；更新只读保护相关测试。
5. 为新版本补充磁盘 fixture、重复加载及世界重开测试，验证新旧值和初始化语义。

## 当前验证与边界

`SaveMigrationAssertions` 使用历史源码字段构造无版本 `.dat` 文件，通过真实 `PersistentStateManager` 加载、保存、重开，分别验证自动／手动模式。它还检查缺省字段、迁移幂等性、仪表 0/50/88/100 读数、未知字段、未来版本强制保存及命令拒绝、非法版本类型和非有限风值。

客户端 GameTest 保存一个缺少方块实体的旧式仪表方块，再重开存档验证恢复与朝向，并继续运行天气／语言／睡眠／跨维度回归。

这不是对全部历史玩家存档、整合包或 Alpha → 1.0 的完整升级矩阵。当前 1.0 尚未实现，未来需要真实存档副本、长期运行以及独立多人环境验证。

## 水下观测候选的方块状态兼容

风向标与气象站新增原版 `waterlogged` 方块状态，默认为 false；已有 ID、风向 `angle`、气象站 `facing` 保持不变。旧状态缺少该属性时使用默认干燥状态。没有新增仪表观测 NBT 或修改天气/风况载荷，不递增 `skysigns_data_version`。风向标浸水时保留原角度，排水后重新跟随服务端风况；气象站水淹保护不保存无效读数。新旧状态反序列化和完整历史存档兼容矩阵仍需分别验证，不能以字段保持不变推导任意降级安全。

## 世界退出同步异常

核对当前依赖 Fabric Client GameTest API 4.2.13+14b92d896f 的源码：`NetworkSynchronizer` 在发送时增加在途计数、接收处理结束时减少计数；计数为负或等待超时会标记非法。客户端退出的 `cancelTasks` 注入点调用 `reset()`。因此“重置时仍有在途包，随后旧接收回调再减计数”是可检验的候选路径，尚未确认本项目历史失败走过该路径。

`SKYSIGNS_NETWORK_DIAGNOSTICS=1` 在退出重置时打印在途计数；非法时输出最近 128 个事件。它有记录开销，不能用于正式性能数字。无该变量时不织入诊断 Mixin。湿度计时 Mixin 仅在 `SKYSIGNS_ISSUE9_MODE=preflight|detailed` 时织入；默认回归及普通客户端帧测量不织入这些计时。

短预检 `network-preflight-1` 完成 0／64／128 台三窗口，场景、读数、每次 245 查询与自然调用次数断言通过，退出 0；此次没有复现同步异常。后续正式测量是否通过，不能用来宣布该间歇问题已修复，也不关闭 Issue #9。

## 普通客户端入口

新增开发任务 `runPerformanceClient`，运行测试源集但不设置 `fabric.client.gametest`。测试客户端入口仅在 `SKYSIGNS_NORMAL_PERF=1` 时启用，启动时断言不存在 GameTest 属性与详细／网络诊断环境变量。它读取隔离实例 saves 下的新建世界副本，不能读取玩家世界。

示例（PowerShell，先设置本机 JDK 21）：

```powershell
$env:SKYSIGNS_NORMAL_PERF='1'
$env:SKYSIGNS_NORMAL_WORLD='issue9-normal-<new-run-id>'
$env:SKYSIGNS_NORMAL_OUTPUT='<new-absolute-output-directory>'
$env:SKYSIGNS_NORMAL_COMMIT=(git rev-parse HEAD)
.\gradlew.bat runPerformanceClient --offline --no-daemon
```

启动前将本任务生成的关闭世界模板复制到 `build/run/performanceClient/saves/<world-name>`；必须使用不存在的新目标，不能覆盖旧副本。`SKYSIGNS_NORMAL_PREFLIGHT=1` 只做短设施预检，不算正式结果。

正式普通客户端按 0→64→128／64→128→0／128→0→64 顺序运行九窗口，每窗口 200 server tick 预热、600 tick 采样。正常集成世界连续运行，正常客户端事件负责调度，不调用 GameTest 等待接口。场景为无水平台、手动雷暴、手动风向 90°／强度 0.5、相机 (8,84,-10)、yaw 0°／pitch 25°、1280×720、VSync 开、120 FPS 上限、视距 5、模拟距离 12、FOV 70、第一人称 spectator。鼠标解除捕获，以避免鼠标移动改变固定相机；相机、焦点、屏幕、暂停和限帧断言保留。

采集的是正常游戏 `WorldRenderEvents.END_MAIN` 回调间隔，不是 GPU 绘制时间或显示器 present 时间。`normal-summary.json` 与 `normal-render-intervals.csv` 是普通客户端结论入口；复用探针的 `summary.json`／`scheduling-diagnostic` 仍是通用调度诊断，不能混作 GameTest 与普通客户端同一指标。

**通过要求同时满足进程退出 0、根级 `result.json` 的 passed=true、无 `failure.json`，并有九个完整窗口。** 普通客户端在失败后保全数据并主动停止，Gradle 可能仍退出 0；不能只看 BUILD SUCCESSFUL。

## 缓存范围评估

本轮建议暂不直接实施或承诺帧收益，保留缓存为服务端重复查询优化候选。当前 128 台自然采样每秒做 31360 次流体查询，存在减少查询的空间，但本机限帧场景没有帧 P95 问题复现，计时还有观测开销。

沿用 PR #15 的每 world、精确 BlockPos、只缓存附近水体布尔值的范围；天气／群系／海拔继续现算，不改变秒采样与错峰。需要特别注意：同位置仪表恰好每 20 tick 采样，若 TTL 为 20 tick 且到期即失效，独立仪表下一次自然采样通常仍会 miss；它主要帮助同位置重复请求，不能承诺优化独立仪表。60／100 tick 才可能跨多次仪表采样，但会引入约 3／5 秒的水体更新延迟，默认值要依据命中率和观测需求选择。

后续若获实施授权，应先验证容量、跨区块卸载失效、不额外加载区块和不完整扫描策略，再对冷热缓存、集中／分散仪表及气象站／forecast 重复请求测查询次数与服务器收益。退出同步异常依旧未定位，不因为本地成功便将 #9 关闭或将 #15 宣布全面通过。
